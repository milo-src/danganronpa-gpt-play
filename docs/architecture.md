# Архитектура расширения

Это план размещения будущего кода. Папки пока служат каркасом; реализации и конфигурации сборки нет.

## Поток данных

```text
Страница ChatGPT
    → adapters/chatgpt: обнаружить сообщение и завершение ответа
    → game/dialogue: получить реплики и игровые команды
    → game/scene или game/trial: обновить состояние игры
    → ui/components: показать сцену, текст, персонажей и эффекты
```

`extension/content` подключает эти части к странице. `extension/settings` отвечает за настройки пользователя. `extension/background` стоит использовать только для задач уровня расширения, которым действительно нужен фоновый обработчик.

## Границы модулей

| Модуль | Что здесь находится |
| --- | --- |
| `src/extension/` | Интеграция с браузером, точки входа, будущий manifest |
| `src/adapters/chatgpt/` | Всё, что зависит от устройства страницы ChatGPT: поиск сообщений, наблюдение за ответом, нормализация текста |
| `src/game/dialogue/` | Разбор реплик, текущая реплика, очередь, скорость текста и история |
| `src/game/scene/` | Фон, персонажи на сцене, эмоции, переходы, воспроизведение аудио и загрузка ресурсов |
| `src/game/trial/` | Состояние суда, улики, игровые события и правила возражений |
| `src/ui/components/` | Отображение состояния игры и обработка действий игрока |
| `src/ui/styles/` | Оформление, адаптация к размеру окна, темы и анимации |
| `src/data/` | Каталоги доступных персонажей; позже — локаций, аудио и тем |
| `public/assets/` | Готовые файлы, которые загрузчик находит по каталогам |

Игровой движок не должен обращаться к DOM ChatGPT напрямую. Адаптер передаёт ему обычные данные: это позволит менять интеграцию со страницей независимо от сцены и диалогов.

Интерфейс стоит монтировать в отдельный корневой контейнер с изоляцией стилей. Настройки пользователя и состояние прохождения должны храниться отдельно от статических каталогов ресурсов.

## Договорённости о ресурсах

- Игровые события обращаются к персонажам по ID и ключу эмоции, например `dr1.makoto-naegi` + `thinking`.
- Путь к изображению определяется через описание персонажа, а не зашивается в компонент диалогового окна.
- `src/data/characters.json` перечисляет только готовые наборы. Папку `_template/` загрузчик не сканирует.
- Неизвестный ключ эмоции заменяется спрайтом по умолчанию; неизвестный персонаж не должен ломать показ текста.
- Загружаемый текст чата обрабатывается как данные. Его нельзя исполнять как код или вставлять как произвольную HTML-разметку.
- `public/` предназначен для копирования в сборку; `source-assets/` и `docs/` в сборку не включаются. Эти правила нужно закрепить в конфигурации, когда будет выбран сборщик.

## Что реализовать первым

1. Минимальное расширение, которое подключает к странице сцену и настройки.
2. Показ одного локального персонажа, фона и тестовой реплики.
3. Адаптер ChatGPT с учётом постепенного появления ответа и защитой от повторного проигрывания.
4. Формат реплик: говорящий, текст, эмоция и необязательная команда смены сцены.
5. Звук, история диалогов и сохранение состояния.
6. Режим суда как отдельный слой поверх готовой сцены и диалогов.

Структура не привязана к конкретному UI-фреймворку. Manifest, package.json и инструменты сборки лучше добавить при реализации первого работающего этапа.
